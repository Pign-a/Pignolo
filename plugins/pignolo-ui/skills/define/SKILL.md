# /pignolo-ui:define

Define the product and the design of this project with the user. The request: $ARGUMENTS

## Values

These are substituted by Claude Code when the skill loads. The support files in `reference/` do not get substitutions, so every command that needs a value takes it from here.

- `<root>` = `${CLAUDE_PLUGIN_ROOT}`
- `<data>` = `${CLAUDE_PLUGIN_DATA}`
- `<N>` = `${user_config.optionsPerDecision}`
- `<profile>` = `${user_config.profile}`
- `<presentation>` = `${user_config.presentation}`
- `<repo>` = the root of the project (the git root of the working directory)

If `<N>` or `<profile>` still starts with `${`, Claude Code did not substitute it: use the default from plugin.json (`<N>` is 3, `<profile>` is balanced) and say so. Never replace `<presentation>` with a default: pass it to `publish-gate` exactly as it arrived.

## How to ask

Words are asked with AskUserQuestion (in the chat, one round per turn of the user, when the session has no such tool): at most 4 questions per round, each with 2 to 4 concrete options taken from what you read in the project, the recommended one first; the user can always write their own answer. What is visual (color, type, shape, style) is never asked in words: it is shown on the board of step 5 and chosen there. Never ask what the project already answers: read first and present what you found as an assumption to confirm. An "Ok" confirms only the question it answers. Nothing is written to the project without a diff the user confirms, and nothing that exists is overwritten.

## Steps

1. **Environment.** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" env`. If `claude.ok` is false, use the sequential path of `options.md` and say so. **Before any call to the Artifact tool:** `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" publish-gate --data <data> --project <repo> --presentation <presentation>`. With any exit other than 0 do not call Artifact at all: the board of step 5 is shown locally (say the reason in one line; an unreadable `<presentation>` gives exit 1 and the line "ajuste `presentation` ilegible: se trabaja en local"). `<board>` is `artifact` with exit 0 and the Artifact tool in this session, otherwise `local`. If the user says "no publiques" at any moment: `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" no-publish --run <run>` and `<board>` is `local` from then on.
2. **What is missing.** Read `<repo>/PRODUCT.md` and `<repo>/DESIGN.md` and apply step 1 of `${CLAUDE_PLUGIN_ROOT}/reference/foundation.md` (what counts as defined). If both are defined, say so in one line, remove the pending lines (step 7) and end: this skill never reopens a decision by itself; to change the design the user asks for it in words. Otherwise say what will be defined, in order (product first, then design), create the run with `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" init --project <repo> --command new --slug define` (it prints `run`: `<run>` below), then `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" norms --run <run>` and `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" leak-values --project <repo> --out <run>/leak-values.json`. Read what the project already says: README, `CLAUDE.md`, `package.json` and the screens that exist.
3. **Product (skip if `PRODUCT.md` is defined).** Ask what is still unknown, in at most 2 rounds: who uses it and in what situation (`Audience`), what they want to know or do first (`First look`), the tone in a few words (`Tone`), what is not wanted (`Not wanted`), what must not change (`Do not touch`). `Audience` and `First look` must come out decided; the other three may stay `undecided` if the user says so. Write the draft to `<run>/product-draft.md` (the five `##` sections, 60 lines at most, the user's words used literally, no names of real people, no emails), show it as the diff of a new file and, only after the user confirms it, run `node "${CLAUDE_PLUGIN_ROOT}/scripts/product-md.mjs" create --project <repo> --from <run>/product-draft.md --values-file <run>/leak-values.json`, which never overwrites. Exit 1 with an invalid draft: fix it with the user and run it again. If `PRODUCT.md` already exists and only lacks `Audience` or `First look`, complete those sections with Edit after a confirmed diff and check it with `node "${CLAUDE_PLUGIN_ROOT}/scripts/product-md.mjs" validate --project <repo> --values-file <run>/leak-values.json`.
4. **Design in words (one round).** Register (`product`: a tool people work in; `brand`: a page that presents something), themes (light, dark or both), density (airy, medium, dense), and anything the brand already fixes (a color, a typeface, a logo the user gives). These answers go into every brief of step 5.
5. **Design on a board.** Say the estimate first (`options.md`, "Before the round"). Load `${CLAUDE_PLUGIN_ROOT}/reference/options.md` and generate `<N>` style tiles with `--kind direction` and `destination: local` (a tile never asks for remote fonts; one round; its brief carries the product context: run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" context --project <repo> --run <run> --values-file <run>/leak-values.json` and paste its `text`, plus the answers of step 4). The tiles are generated blind to the styles that are in the code today.
   - **If the project already has styles and no decided `DESIGN.md`:** run `node "${CLAUDE_PLUGIN_ROOT}/scripts/design-md.mjs" extract --project <repo> --out <run>/design-proposal.json` and keep its tokens as one more direction, labelled `lo que ya hay`. Exit 1 with `mode: exists` (a `DESIGN.md` with the mark is there): its own tokens are that direction. Any other exit 1: there is no such direction, say so.
   - **Build the board:** write `<run>/board/index.html` with Write: one self-contained page, one column or band per direction (A, B, C and `lo que ya hay`), each rendering the same specimen with the tokens of the `:root` of that tile (or of the proposal): the palette as labelled swatches with their values, the type scale with a real heading and paragraph from the product, a primary and a secondary button with hover and focus states, an input with its label, a card, and the light and dark theme when both were chosen. Same content in every band, so only the direction changes. System font stacks only; no script, no remote resource of any kind. No project code, no captures, no names of people.
   - **Check it:** `node "${CLAUDE_PLUGIN_ROOT}/scripts/leak-check.mjs" --dir <run>/board --values-file <run>/leak-values.json`. Anything found: fix the board; if it cannot be fixed, show it locally.
   - **Show it.** With `<board>` `artifact`, ask the gate again now that the run exists: `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" publish-gate --data <data> --project <repo> --presentation <presentation> --run <run>`; any exit other than 0 means `local`. With exit 0: say in one line that the board goes to a page that is private to the user's claude.ai account and what travels (the tokens of each direction, a heading and a paragraph about the product and, in `lo que ya hay`, the colors and fonts found in the code), then call Artifact with `file_path` `<run>/board/index.html` and nothing else that changes who can see it; never pass `force`, `share` or `capabilities`. Quote the URL. If the call fails or the result does not say the page is private, say so and show it locally. With `local`: tell the user the path of `<run>/board/index.html` and open it; say `tablero: local (<reason>)`. Deleting the published page is the user's decision.
   - **The user chooses in their own turn** (a letter, `lo que ya hay`, or a combination such as "B with the type of A"). A combination is built by you as a new tile in `<run>/direction-<next letter>/`, checked with `options-check` and added to the board before saving. One adjustment round at most; after it, what is left is reported as pending.
6. **Save DESIGN.md.** Write the user's literal quote to `<run>/choice.txt`.
   - **A generated direction:** first `node "${CLAUDE_PLUGIN_ROOT}/scripts/leak-check.mjs" --dir <run>/direction-<X> --values-file <run>/leak-values.json`, then approve.mjs save --flow direction: `node "${CLAUDE_PLUGIN_ROOT}/scripts/approve.mjs" save --project <repo> --flow direction --from <run>/direction-<X> --values-file <run>/leak-values.json` (the flow is always `direction`; keep the `path` it prints as `<approved>`: `design/approved/direction`, or `-v2` when one was already there). Then create `DESIGN.md` from the template with the tokens of the `:root` of the chosen tile and the register of step 4: write the operations to `<run>/design-ops.json` and show the diff with `node "${CLAUDE_PLUGIN_ROOT}/scripts/design-md.mjs" patch --file "${CLAUDE_PLUGIN_ROOT}/templates/DESIGN.md" --ops <run>/design-ops.json` (it writes nothing). Only after the user confirms it, run the same command adding `--out <repo>/DESIGN.md`, which creates the new file and never overwrites. Never use `--write` on the template. Only then approve.mjs record: `node "${CLAUDE_PLUGIN_ROOT}/scripts/approve.mjs" record --project <repo> --path <approved> --quote-file <run>/choice.txt`, show its diff and, after the user confirms, the same command with `--write`.
   - **`lo que ya hay`:** build `DESIGN.md` from the proposal the same way (`design-md.mjs patch` on the template, diff, `--out <repo>/DESIGN.md`), without the mark `extraídos, no decididos` and with nothing in `pignolo.extracted`: the user chose them, they are decided. Add the quote to its `## Decisions` with Edit after a confirmed diff.
   - **A `DESIGN.md` that exists with the mark:** `design-md.mjs patch --file <repo>/DESIGN.md --ops <run>/design-ops.json` (then `--write` after the confirmed diff) with the chosen tokens and one `remove-item` per entry of `pignolo.extracted`: emptying that list drops the mark. If the list was not there, delete the line of the mark with Edit after a confirmed diff. Read the file again: the mark must be gone.
   - Then `node "${CLAUDE_PLUGIN_ROOT}/scripts/design-md.mjs" validate --file <repo>/DESIGN.md --project <repo>`: a finding is fixed with a confirmed diff; exit 2 is "no verificado" with the reason.
7. **Close.** If `<repo>/CLAUDE.md` has the section `## pignolo-ui: pendientes`, remove the lines of the files that are now defined (and the section, if it is left empty) with Edit after a confirmed diff; touch nothing else in that file. Report in a few lines: which files were created or completed, the chosen direction with the user's quote, where the board is, what stayed `undecided`, and what to run next (`/pignolo-ui:new` for a new screen, `/pignolo-ui:improve` or `/pignolo-ui:audit` for the ones that exist: the styles in the code are not yet the ones of `DESIGN.md`). This skill changes no screen and no style of the project.

## Limits

Two rounds of product questions, one of design questions, one round of directions plus at most one adjustment. When a limit is reached, what is left is reported as pending and the flow ends. If the user stops halfway, what was confirmed stays written and the next run of this skill starts from what is still missing.

- The board goes to a private page of the user's claude.ai account when the gate allows it and the tool is there; with `publish: never`, `presentation = local`, "no publiques" or no tool it is a local page and nothing leaves the machine.
- Exit 1 of a script is a finding or a refusal; exit 2 is "no verificado" with the reason. Never turn "did not run" into "passed".
- The agent does not commit `PRODUCT.md`, `DESIGN.md` or `design/approved/`: that is the user's decision.
