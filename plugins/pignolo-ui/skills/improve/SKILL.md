# /pignolo-ui:improve

Improve the screen the user names (a local URL or a file). The request: $ARGUMENTS

## Values

These are substituted by Claude Code when the skill loads. The support files in `reference/` do not get substitutions, so every command that needs a value takes it from here.

- `<root>` = `${CLAUDE_PLUGIN_ROOT}`
- `<data>` = `${CLAUDE_PLUGIN_DATA}`
- `<N>` = `${user_config.optionsPerDecision}`
- `<profile>` = `${user_config.profile}`
- `<presentation>` = `${user_config.presentation}`
- `<repo>` = the root of the project (the git root of the working directory)

If `<N>` or `<profile>` still starts with `${`, Claude Code did not substitute it (a setting the user never saved arrives like that): use the default from plugin.json (`<N>` is 3, `<profile>` is balanced) and say so. Never replace `<presentation>` with a default: pass it to `publish-gate` and `present` exactly as it arrived. An unsubstituted `<presentation>` is read by the scripts as local, so nothing is published (D-4c-15).

## Foundation gate

This skill does not work on a project whose product and design are not defined. Right after step 1 and before step 2, read `<repo>/PRODUCT.md` and `<repo>/DESIGN.md`, load `${CLAUDE_PLUGIN_ROOT}/reference/foundation.md` and follow it. If either is missing or undecided, stop and send the user to `/pignolo-ui:define`; go on without it only after the user asked for that explicitly, twice, as that file says, with the pending note in the project's `CLAUDE.md`. An "Ok" is not that request. **A missing or undecided `DESIGN.md` cannot be skipped in this skill, however explicit the request:** end the command and send the user to `/pignolo-ui:define`. Only a missing `PRODUCT.md` can be skipped. Step 2 never starts before this gate is passed or explicitly skipped.

## Steps

1. **Environment.** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" env`. The first line you print to the user is `pignolo-ui <pluginVersion>`. If `claude.ok` is false, use the sequential path of `options.md` and say so. **Before any call to the Artifact tool, also before `action: "list"`:** `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" publish-gate --data <data> --project <repo> --presentation <presentation>`. With any exit other than 0 (1 is a refusal; 2 is an error, such as a project.json that cannot be read) do not call Artifact at all: use `--artifact no --design-type no` below and work locally (say the reason in one line; an unreadable `<presentation>`, the literal text that was not substituted, gives exit 1 and the line "ajuste `presentation` ilegible: se trabaja en local"). With exit 0 and the Artifact tool in this session, call it with `action: "list"` and `scope: "types"`: `--design-type yes` only if a listed type has the exact title "Design"; once the run exists (step 2) write its `type_url` to `<run>/types.json` with Write as `{ "design": "<type_url>" }`, never typed by hand. Publishing happens only through `canvas-index.mjs plan` (see `present-and-choose.md`).
2. **Inspect (only after the foundation gate).** Load `${CLAUDE_PLUGIN_ROOT}/reference/prepare-run.md` and follow it with command `improve`: URL or path, then the batch inspection (`measure`, `capture`, `dom`, `check`). That is the "before"; it is never written again. Load `${CLAUDE_PLUGIN_ROOT}/reference/context.md` and run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" context --project <repo> --run <run> --values-file <run>/leak-values.json` (its first lines say how to create that file): say its `line` once when it is not null. Then dispatch the auditor as in `/pignolo-ui:audit` (`subagent_type: "pignolo-ui:ui-auditor"`, `model: "opus"`, only the path of the run), copy its `json` block unchanged to `<run>/auditor.json` and run `run.mjs auditor-check`. If the problem is in `DESIGN.md`, first propose completing it as a diff the user confirms.
3. **Symptom menu, in the chat.** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" menu --run <run>` and show the numbered list in the user's words, pre-ticked with what the scripts found, with the symptom id in parentheses at the end of each line. The user answers in their own turn. Save their words to `<run>/words.txt` and translate them with `run.mjs menu --run <run> --words-file <run>/words.txt` (`matched`). In the same round ask one more question: what must not be touched (`nada` is a valid answer). Never decide the symptoms for them.
4. **Versions.** First decide how they will be shown: step 1 of `${CLAUDE_PLUGIN_ROOT}/reference/present-and-choose.md` (`run.mjs present`, it prints the `destination` that the briefs need). Then load `${CLAUDE_PLUGIN_ROOT}/reference/options.md` and generate `<N>` improved versions of the screen, each a navigable HTML flow, one round plus at most one regeneration. Write `<run>/brief.md` first (`## First look` of the "before" and `## Do not touch` with the answer of step 3; `context.md`, part 2), run `context` again with `--brief <run>/brief.md` and paste its `text` into each brief. Give each the findings the user chose, a text summary of the "before" capture (never the image) and the `keep` line of the auditor (what already works and must not be diluted), if it has one.
5. **Present and choose.** Load `${CLAUDE_PLUGIN_ROOT}/reference/present-and-choose.md`: the canvas (one per run, private, one line of notice and no question) or the local page. The user chooses or combines in their own turn. What they choose is saved as approved: `approve.mjs save ... --brief-file <run>/brief.md` and `approve.mjs record` (the diff is shown and the user confirms before `--write`), as described in that file.
6. **Apply.** Load `${CLAUDE_PLUGIN_ROOT}/reference/apply.md` with the approved path: a batch of at most 5 files and 200 lines, tokens first, verified, reverted only after showing what `restore` will delete.
7. **Confirm (at most once), in `<run>/after/`.** The "after" never overwrites the "before": run, in this order, `node "${CLAUDE_PLUGIN_ROOT}/scripts/browser.mjs" measure --project <repo> --run <run>/after --url <URL> --before <run>/browser.json` (or `--file <path>`), then `capture` and `dom` with the same arguments except `--before` (that flag only goes with `measure`; same widths and themes), then `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" check --project <repo> --run <run>/after --files <touched files> --base <base> --before <run>/ui-check.json` (the "before" reading: what the page already failed is debt, not new). Write nothing into `<run>/` itself: everything of the "after" goes in `<run>/after/`. Build the before and after: closed findings (each citing the data of the second reading), new findings (floor rules block), debt left untouched, and the structural comparison with the approved decision (write `<run>/after/map.json` first, as `{ "<screen>.html": "<local URL or project path of that screen>" }`): `node "${CLAUDE_PLUGIN_ROOT}/scripts/compare.mjs" approved --project <repo> --approved <approved> --map <run>/after/map.json --run <run>/after`. That comparison is informational only: differences are reported and never block. If the user chose at least one `J-nn` criterion in step 3, add the verdict pass of `context.md` (part 4: `run.mjs verdict-request`, about 0.3 USD, only runs with a chosen `J-nn`; copy `<run>/run.json`, `<run>/norms.md`, `<run>/product.md` and `<run>/brief.md` (the ones that exist) into `<run>/after/` first): it never changes what `run.mjs verdict` says and it is not a second confirmation.
8. **Report.** Build the skeleton with `run.mjs report-skeleton --project <repo> --run <run>/after --implements <approved>`, add the text of each claim you keep, run `node "${CLAUDE_PLUGIN_ROOT}/scripts/report-check.mjs" --project <repo> --run <run>/after` and then `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" verdict --project <repo> --run <run>/after --build-ok yes|no`, where `yes|no` is the result of the first `typecheck`, `build` or `lint` script of `package.json` that you ran (`apply.md` step 5); leave `--build-ok` out only when the project declares none. A project that declares one and gets no `--build-ok` is `sin verificar`. The `status` it prints is the word of the report; say "terminado" only when the verdict says `terminado`. The first line of the report comes from `run.mjs report-line` (subagents launched of requested, model as requested).

## Limits (spec section 6)

One batch inspection, one round of versions (plus at most one regeneration), one batch of fixes, at most one confirmation. When a limit is reached, what is left is reported as pending and the flow ends.

- Every version (mockup, capture and diff) stays in the run folder.
- Versions go to a private canvas of the user's claude.ai account when the account has the "Design" type and nothing says otherwise; with `publish: never`, `presentation = local`, "no publiques" or no tool or type they are shown with the local `compare.html` page and nothing is published. The first line of the report says which (`run.mjs report-line` with `canvas`: `published` or `local-fallback` and its `reasons`).
- Exit 1 of a script is a finding; exit 2 is "no verificado" with the reason.
