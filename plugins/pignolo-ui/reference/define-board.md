# The board of define, in the canvas of the project (loaded by /pignolo-ui:define, step 5)

Markers: `<root>` is the plugin root, `<data>` the plugin data folder, `<presentation>` the user's presentation setting, `<repo>` the project root, `<run>` the run folder, `<board>` is `canvas`, `artifact` or `local` (step 1 of the skill) and `<X>` the letter of the chosen direction. The skill resolves them in its "Values" block; replace them before running anything. Every command prints one JSON object: exit 0 is done, exit 1 is a finding or a refusal, exit 2 is "no verificado" with the reason.

The board is one page, `<run>/option-A/board.html` (one file, system fonts, no script, no remote resource), checked with `leak-check.mjs" --dir <run>/option-A` before anything leaves the machine. It is shown in one place, never both a canvas and a page of its own.

1. **Canvas (`<board>` is `canvas`: the gate allowed it and the account lists the type "Design").** Ask the gate again now that the run exists: `node "<root>/scripts/run.mjs" publish-gate --data <data> --project <repo> --presentation <presentation> --run <run>` (any exit other than 0 means `local`). Then `node "<root>/scripts/run.mjs" present --data <data> --project <repo> --presentation <presentation> --kind option --artifact yes --design-type yes --run <run>`: `--kind option` because the board is a page, not a tile (`--kind direction` is always local). With `mode: canvas`, say its `notice` in one line, as it is, and follow step 3 of `present-and-choose.md` with these values: `node "<root>/scripts/canvas-index.mjs" build --project <repo> --run <run> --options A --screens board.html --platform desktop --row-title "Tablero" --page-name "Definición · <YYYY-MM-DD>" --design none --first <the one `present` printed>` (no `--heights`), then `verify`, `node "<root>/scripts/canvas-index.mjs" plan ...`, the read, `merge`, `record` and the refusals exactly as there (the canvas is the one of the project: its page is added to it). The row note says `Tablero` instead of `Opción A`. If `present` says `mode: local`, or `build`, `plan` or `merge` stop (exit 1 or 2), say so in one line and go to 2 when the Artifact tool is there, else to 3.

2. **A private page of its own (`<board>` is `artifact`, or the way out of 1).** The gate with `--run <run>` as in 1. Say in one line that the board goes to a page that is private to the user's claude.ai account and what travels (the tokens of each direction, a heading and a paragraph about the product and, in `lo que ya hay`, the colors and fonts found in the code), then call Artifact with `file_path` `<run>/option-A/board.html` and nothing else that changes who can see it; never pass `force`, `share` or `capabilities`. Quote the URL. If the call fails or the result does not say that the page is private, say so and go to 3. Deleting the published page is the user's decision.

3. **Local.** Tell the user the path of `<run>/option-A/board.html`, open it and say `tablero: local (<reason>)`.

After the choice (a letter, `lo que ya hay` or a combination): rewrite `<run>/option-A/board.html` with only the chosen direction (the same specimen, one band; a combination is built as in the skill and shown first) and republish it in place, never both places. In the canvas: `canvas-index.mjs" build` again with the same arguments and the loop of step 3 of `present-and-choose.md`: the artboard keeps its name, only its bytes change, and what the user moved or added in the canvas stays. In its own page: call Artifact again with the same url and the same `file_path`. Local: open the file again. The canvas, or the page, then shows only the direction that was chosen.
