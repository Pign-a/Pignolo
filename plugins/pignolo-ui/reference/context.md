# Product context, the brief of the screen and the verdict pass (shared by new, improve and audit)

Markers: `<root>` is the plugin root, `<repo>` the project root, `<run>` the run folder, `<ids>` a comma-separated list of ids. The skill resolves `<root>` in its "Values" block; replace the markers before running anything. Every command prints one JSON object; exit 0 is done, exit 1 is a finding or a refusal, exit 2 is a usage error or "no verificado" with the reason.

1. **Context of the run.** The scripts that copy a file of the user into the run check it for leaks first, with the values of `run.mjs leak-values` (`node "<root>/scripts/run.mjs" leak-values --project <repo> --out <run>/leak-values.json`, once per run). Then `node "<root>/scripts/run.mjs" context --project <repo> --run <run> --values-file <run>/leak-values.json`. It reads `PRODUCT.md` at the root of the project (optional, 60 lines at most, sections `Audience`, `First look`, `Tone`, `Not wanted`, `Do not touch`), copies it byte by byte to `<run>/product.md` and names it in `run.json`. It prints `{ product, brief, text, line }`. When `line` is not null, say it once, at the start, in one line ("sin PRODUCT.md: se sigue sin contexto de producto", or that the file is ignored and why): a missing or invalid `PRODUCT.md` never stops the flow. `text` is the bounded context that goes into the brief of every option (`options.md`, "The brief"); the auditor reads `<run>/product.md` and `<run>/brief.md` by itself.

2. **The brief of the screen.** Write the confirmed brief to `<run>/brief.md` with Write, in this format and at most 60 lines: `## Screen` (what it is, optional), `## First look` (required: what shows without scrolling and where the main action is), `## Do not touch` (required: what must not change; `nothing` is valid) and, only when this screen differs from `DESIGN.md`, a line `Register: product` or `Register: brand`. Then run `context` again with `--brief <run>/brief.md`: it validates the brief (exit 1: fix it with the user, it is text they just confirmed) and its `text` now carries the first look and what is not touched. The brief travels with the approved version: `approve.mjs save ... --brief-file <run>/brief.md` seals it in the manifest, and `verify` blocks a changed or deleted `brief.md`. The style tiles (`direction`) take no brief. `node "<root>/scripts/run.mjs" register --project <repo> --brief <run>/brief.md` prints `{ register, source }`: the brief's line, else the one in `DESIGN.md`, else `unset`.

3. **Creating `PRODUCT.md` (only in `new`).** Once per run, after the brief is confirmed and with "no" as the default: build a draft from what the user already answered (who uses it for `Audience`, the main action for `First look`, what they said they do not want for `Not wanted`, what must not change for `Do not touch`; any other section stays `undecided`; no new questions), write it to `<run>/product-draft.md` and show it as a diff of a new file. `PRODUCT.md` is created only with a diff the user confirms, with `node "<root>/scripts/product-md.mjs" create --project <repo> --from <run>/product-draft.md --values-file <run>/leak-values.json`, which writes with `wx` and never overwrites. `improve` and `audit` never create it: they only say the `line`.

4. **The verdict pass (only in `improve`).** In the confirm step, and only when the user chose at least one `J-nn` criterion: `node "<root>/scripts/run.mjs" verdict-request --run <run> --chosen <ids>` with the `rules` of the symptoms the user chose (it keeps the `J-nn` ones). Exit 1 `no-judgment-chosen`: there is nothing to judge, the pass does not run, say nothing. Exit 0: say one line with its `costLine` (about 0.3 USD) and dispatch the same auditor (`subagent_type: "pignolo-ui:ui-auditor"`, `model: "opus"`, only the path of `<run>/after`; it finds `verdict-request.json` there and answers in verdict mode). Copy the last `json` block unchanged to `<run>/after/verdicts.json` and run `node "<root>/scripts/run.mjs" auditor-check --project <repo> --run <run>/after --mode verdict`; on exit 1 send the problems back to the auditor once. Show each result as "resuelto / parcial / sin resolver (juicio del auditor)"; `parcial` and `sin resolver` are reported as pending. It is a judgment, not a measure: it never changes what `run.mjs verdict` says ("terminado" does not depend on it) and it is not a second confirmation, it is the same one with one more reading.
