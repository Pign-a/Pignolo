# Screen brief

Write it before drawing a new screen. A screen without a brief tries to serve two jobs at once and comes out overloaded; with one, every element has a reason to be there. Keep it to about ten lines, in the conversation or saved as `design/screens/<slug>/brief.md` so later changes can be checked against it.

- **User**: who, in what situation, how often.
- **Job**: the one thing they come to do (verb + object).
- **Primary action**: one label, verb + object. If two actions compete to be the primary one, these are two screens: say so in one line to the author and continue with the first.
- **Key data**: up to 3 items. If more than 3 matter equally, split the screen or move the extra ones to the next item.
- **Left out on purpose**: what is not on this screen and where it lives instead. Writing it down is what stops the screen from growing.
- **Regions**: in reading order, as text, each with its one dominant element. No wireframe file: text is enough to fix the structure before styling.

The limits (3 data, one action) are starting guidance, not a gate: if the screen really needs more, say why in the brief and go on.
