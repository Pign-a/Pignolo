## Decisiones del autor ya tomadas (2026-10-01, marcadas DECIDIDA)

- **D-FS-A: esqueleto SIEMPRE (DECIDIDA).** En proyecto nuevo y en existente, **solo para lo que no es código** (el framework manda en el código): `docs/specs/`, `docs/plans/`, `docs/research/`, `docs/references/` (material del cliente que se versiona; solo si el repo es privado: `init` pregunta si es público), `design/` (pignolo-ui), `local/` (privada, ignorada por su propio `.gitignore` con `*`; en equipo `init` muestra la línea para el `.gitignore` compartido y la agrega el humano) y `.pignolo/`. Cada carpeta creada lleva un README corto que dice qué va ahí (reemplaza al `.gitkeep`). Nombres en inglés por defecto.
- **D-FS-B: en un proyecto existente, `init` primero VALIDA y propone ADAPTAR (DECIDIDA).** El usuario elige por ítem entre: **adoptar** la carpeta existente como ese lugar (se anota en el mapa, no se mueve), **mover/renombrar** al lugar recomendado, o **dejarlo**. Un movimiento no rompe nada: vista previa con la lista exacta, `git mv` si está versionado (renombre simple si no), nunca pisa, nunca cruza un junction o symlink (`realpath`), se niega con el índice sucio en esas rutas, deja registro para **deshacer**, y **antes de mover** busca en el repo referencias a la ruta vieja (enlaces markdown, imports, configuración, CI, `.gitignore`, scripts de `package.json`) y las muestra: las que se pueden reescribir sin riesgo (enlaces relativos de markdown) se reescriben en el mismo paso; **todo lo demás se lista y ese ítem queda por defecto en "adoptar en el lugar"** salvo que el usuario insista. **Nunca se mueven archivos de código.** Tras aplicar corre la compuerta o el comando de test que el proyecto declare; si falla, ofrece deshacer (la corre la skill como comando aparte, R-25).
- **D-FS-C: el mapa (DECIDIDA).** Sección `places:` de `.pignolo/project.md` (tipo → carpeta) es la fuente de verdad. Un script contesta "¿dónde va esto?" y lista lo suelto (sin versionar y sin ignorar en la raíz) y los archivos de un tipo conocido fuera de su lugar. **Mal ubicados: avisa Y ofrece mover** con la misma maquinaria segura y el sí del usuario (informe en `/pignolo:status` y en `close-session`; nunca bloquea).
- **D-FS-D: la skill `plan` lee el mapa (DECIDIDA)** en vez de `docs/specs` y `docs/plans` fijos (cambio de contrato; los valores de hoy son los defaults).
- **D-FS-E: a los agentes se les dice el lugar por la tarjeta de tarea o el brief (una ruta), no con un árbol (DECIDIDA).**
- **Sin A/B antes de construir (DECIDIDA).**

## Global Constraints

- Node ≥ 22, sin dependencias npm. `npm test` para la suite completa, nunca `node --test tests/`.
- Nombres de elementos en inglés; texto interno de skills y agentes en inglés; mensajes al humano, commits y docs en español. Conventional Commits con `git commit -F <archivo>`; archivos LF sin BOM; nada de texto largo por comillas de la shell (regla 6 de `rules/core.md`).
- **Nada se borra, nada se pisa, nada se mueve sin vista previa y sin el sí.** Ningún código de este hito llama a `rm`, `unlink`, `rmSync` (salvo temporales de tests con `makeTempDir()`), `git reset`, `git checkout <ref> -- <ruta>`, `git clean`, `stash`, `commit`, `add` ni `push`. **Únicos movimientos permitidos:** `git mv` (un solo origen por llamada) o `fs.renameSync` dentro de `lib/safe-move.js`, y solo a un destino que **no existe**. **Única excepción declarada a "nada se borra":** `fs.rmdirSync` (no recursivo) de las carpetas vacías que el propio movimiento creó (`createdDirs` del registro; si no están vacías no se tocan). Un test lee el registro de `run` de un flujo completo (después de afirmar que **no está vacío**) y afirma que los verbos de git usados están en la lista cerrada `status`, `ls-files`, `rev-parse`, `mv`, `worktree`, `check-ignore`, `config`, `diff`, y que cada llamada `mv` trae exactamente dos rutas (un origen, un destino).
- **Todo archivo cuyo contenido cambie se respalda antes, fuera del árbol** (`backupFile` de `lib/init-actions.js`: `<PIGNOLO_HOME>/init-backup/<sha12 de la ruta del principal>/<ts>/<ruta relativa>`; nunca junto al original). **Todo archivo nuevo se crea con flag `wx`** (falla si existe), nunca con `atomicWrite` (que reemplaza); los archivos reescritos usan temp + rename.
- **Todo movimiento deja un registro que permite deshacerlo, escrito ANTES del primer movimiento** (write-ahead): `<PIGNOLO_HOME>/init-backup/<sha12>/<ts>/moves.json` (R-12).
- Scripts nuevos: salida JSON por stdout; exit 0 ok, 1 fallo con `kind` estructurado (`{ ok, refused?: '<motivo>', reason, ... }`), 2 uso incorrecto, **3 = no se pudo dejar el estado consistente** (movimiento a medias: se detiene, informa y ofrece deshacer); cada fallo con `Alternativa:` en stderr. `places.js report` sale siempre 0 con el repo legible.
- Escrituras atómicas (temp + rename) para lo que cambia, LF sin BOM para lo que se crea. Temporales solo con `makeTempDir()`/`makeRepo()` de `tests/helpers.js`; todo test usa `PIGNOLO_HOME` temporal. Los tests que crean un junction lo quitan en `t.after` (`fs.rmdirSync(enlace)`) **antes** de que el limpiador de temporales recorra el directorio.
- Todo git entra por un ejecutor inyectable (`opts.run`) y todo test que afirme "no se llamó a X" afirma antes que el registro no está vacío. **Los listados de git son con `-z`, sin `trim` y con `maxBuffer` amplio** (helper `gitList` de `lib/safe-move.js`: parte por NUL; un fallo del listado es `refused: 'scan-failed'`, nunca "sin resultados").
- **Raíz de trabajo = checkout principal** (`mainRoot(cwd)` de `lib/disabled.js`, R-2 del hito 8). Fuera de un repo: `refused: 'not-a-repo'`.
- **Windows primero** (la máquina del autor): `lstat` ve los junctions como enlaces (medido) pero **`readdirSync({ recursive: true })`, `statSync` y `existsSync` los atraviesan, y git también** (medido): todo recorrido de árbol de este hito es **manual** (`withFileTypes`, sin seguir `isSymbolicLink()`; `recursive: true` está prohibido en `readdirSync`, un test lo busca en el código) y todo archivo que se vaya a leer, escribir o mover pasa antes por `isLinkOrOutside` (R-7). La comparación de rutas es insensible a mayúsculas; nombres reservados (`CON`, `NUL`, `AUX`, `PRN`, `COM1..9`, `LPT1..9`), rutas ≥ 260 caracteres y nombres con punto o espacio final se rechazan. Los tests de junction crean un junction real con `fs.symlinkSync(dest, link, 'junction')` y se saltan (`t.skip`, con la razón) solo si el sistema no permite crearlo.
- El repo es público: fixtures sintéticos; nada de datos del proyecto del autor.
- Claves nuevas **aditivas**: un `project.md` sin `places` se lee igual y las skills usan los defaults y lo dicen (salvo `reference`, que no tiene default: R-4).
- Versión: la siguiente a la última publicada (hoy 0.12.1 → 0.13.0; ajustar al ejecutar según lo que salga antes) y entrada en el CHANGELOG (CLAUDE.md). **Unir y publicar son del autor.**

## Review Focus (la seguridad de los datos primero)

1. **Un movimiento pierde o pisa datos.** Destino que existe, destino dentro del origen, origen que es un enlace o contiene uno, dos movimientos que chocan, un movimiento a medias, el deshacer que no deshace. Dueñas: **Tasks 2 y 6**. Revisar primero: `lib/safe-move.js` (`planMoves`, `applyMoves`, `undoMoves`) y su registro write-ahead.
2. **Una operación sale del proyecto por un junction o symlink** (la lección de pignolo-ui 0.6.1, C-1; medido en Windows: `git mv` hacia un destino bajo un junction escribe **afuera** y sale 0; `git status` y `git add` traspasan el junction). Cada componente de cada ruta (origen, destino **y sus padres**), cada archivo del árbol movido, cada archivo que se lee o reescribe y cada carpeta que crea el esqueleto pasa por `isLinkOrOutside`. Dueña: **Task 2** (la función), usada en **Tasks 3, 4, 5 y 7**.
3. **Una reescritura de referencias rompe algo que andaba.** Solo se reescribe lo que se prueba seguro, por bytes y solo el destino del enlace; todo lo demás se lista y frena el movimiento por defecto. Dueña: **Task 3**.
4. **Un movimiento mueve código o rompe el proyecto.** La decisión es **por lista de extensiones permitidas** (falla cerrada), no por lista de prohibidas; las carpetas de otras herramientas son solo adoptables. Dueñas: **Tasks 2, 4 y 6**.
5. **El deshacer pisa trabajo posterior o no funciona.** Decide por el disco y no por el índice, valida todo antes de mover, es idempotente y retomable. Dueña: **Task 2** (`undoMoves`).
6. **El plan aprobado no es lo que corre** (preview viejo). `init.js apply` con `adapt` exige `--expect`; el stamp incluye el listado de cada árbol; `applyMoves` vuelve a validar cada ítem justo antes de moverlo. Dueñas: **Tasks 2, 6 y 8**.
7. **Un movimiento deja visible lo que era privado o ignorado.** Lo ignorado viaja con la carpeta pero la regla que lo ignoraba puede quedar afuera (medido): se niega, no se avisa. `private` nunca se mueve; `reference` no existe sin declarar. Dueñas: **Tasks 2, 5 y 6**.
8. **Un subagente mueve archivos.** Se le niega a todo subagente la ejecución de `places.js` entero. Dueña: **Task 9**.

## Rulings del plan (técnicos, registrados)

- **R-1: seis tipos cerrados, en inglés.** `spec`, `plan`, `research`, `reference`, `design`, `private`. Defaults de **cinco**: `docs/specs/`, `docs/plans/`, `docs/research/`, `design/`, `local/`. **`reference` no tiene default** (R-4); su lugar recomendado `docs/references/` (`RECOMMENDED_REFERENCE`) solo lo usa `init` cuando el humano contestó que el repo es **privado**. No entran: el código y los tests (los decide el framework), `scripts/` (es código), las decisiones (viven en `.pignolo/state/decisions/`) y `.pignolo/`, que es siempre `.pignolo/` y no está en el mapa. Un tipo desconocido en `places` se ignora con aviso (como cualquier clave desconocida de `project-config`).
- **R-2: el mapa es `places:` en `project.md`, mapa de un nivel de `yaml-lite`** (tipo → ruta escalar con `/` y barra final), como `gates`. Se agrega `['places', 'places', 'map']` a `KEYS` de `lib/project-md.js` y `places` a `KNOWN` de `lib/project-config.js`. **Un solo escritor del mapa: el paso `project-md` de `init`** (por la fusión de 8a, que no cambia un valor ya declarado: si `places.spec` existe con otro valor y `init` propone otro, va a `conflicts`). El paso `adapt` **no escribe `project.md`**: devuelve `places` (lo adoptado o movido) y `init.js` se lo pasa a `project-md` como `proposal.places`. Lo único que más escribe en `project.md` es el **deshacer**, con una edición puntual de una línea (`revertPlaces`, R-12).
- **R-3: validación de una ruta del mapa (`validatePlacePath`) y qué cuenta como test.** Relativa; separador `/` (un `\` se rechaza); sin `..`, sin `.` como segmento, sin segmentos vacíos, sin letra de unidad (`C:`), sin raíz; ≤ 100 caracteres; cada segmento sin nombre reservado de Windows, sin punto ni espacio final, sin caracteres `<>:"|?*`; **no** dentro de `.pignolo/`, `.git/`, `.claude/` ni `node_modules/`; **no** igual ni dentro de un nombre que reserva un framework (`src`, `app`, `pages`, `public`, `lib`, `test`, `tests`, `cmd`, `internal`, `packages`, `apps`, `bin`, `build`, `dist`); normaliza con una barra final. **`test-paths`, `high-risk-paths`, `contracts` y `serial-paths` cuentan SOLO si están declarados en `project.md`** (`config.testPathsDeclared`; los defaults `*test*` y `*spec*` de `lib/project-config.js` **no cuentan**: `*spec*` casa `docs/specs/`, medido) y se aplican **archivo por archivo** del árbol (`declaredPatternFor(config, relFile) → patrón|null`), no por el nombre de la carpeta; el rechazo nombra el patrón (`inside-test-paths`, `detail: '<patrón>'`). Dos tipos con la misma ruta (sin distinguir mayúsculas) o uno dentro del otro se rechazan. El valor inválido de un tipo declarado se descarta con aviso y se usa el default (o ninguno para `reference`). **Migración de un `project.md` existente:** sin `test-paths` no hay nada que migrar (los defaults ya no frenan nada); con `test-paths` declarado que casa documentos (por ejemplo `*spec*`, que 8a pudo escribir), `adapt` deja el ítem en `adopt` con el patrón nombrado y `init` muestra "ese patrón casa tus documentos: acotalo (por ejemplo `**/*.spec.*`) y volvé a correr `init`"; pignolo **no edita un valor declarado** (R-4 del hito 8). Anclar los defaults de `lib/project-config.js` cambia el contrato de la compuerta: queda en `docs/gaps.md` para el autor, fuera de este hito.
- **R-4: el lugar de un tipo (`resolvePlaces`).** Devuelve para cada tipo `{ kind, path, source: 'declared'|'default'|'undeclared' }`. Quitar un tipo del mapa lo deja en `default` (los cinco con default) y las skills lo dicen. **`reference` solo existe si está declarado** (si no: `source: 'undeclared'`, `path: null`, `where reference` sale con `declared: false` y aviso). `init` escribe `places.reference` **únicamente** cuando el humano contestó que el repo es privado (`answers.public === false`); `answers.public` ausente = **público** (falla cerrada). Quien necesite un lugar para el material del cliente en un repo público usa `local/`.
- **R-5: el esqueleto crea lo que no existe, nunca lo que ya hay, y nunca fuera del proyecto.** Por tipo declarado (o adoptado, o con default) cuya carpeta no existe: la crea con un `README.md` corto (plantilla `templates/places/<kind>.md`, **solo en inglés**: `skeleton` corre antes que `project-md` y en un proyecto nuevo no hay idioma). Si la carpeta existe: no escribe nada (ni README: es del humano). Sin `.gitkeep`. Toda ruta que crea pasa antes por `isLinkOrOutside` (componentes y primer ancestro existente) y todo archivo nuevo se crea con flag `wx`. Una carpeta cuyo nombre solo difiere en mayúsculas de otra existente (`Docs/` y `docs/`, comparado con el nombre real del disco por `readdir` del padre) se rechaza (`case-collision`). Si la ruta existe y es un archivo: `not-a-dir`. `design/` se crea con su README **pero `design/approved/` es de pignolo-ui y no se crea**. Un tipo `leave` con candidata existente **no** recibe su carpeta default al lado (R-14).
- **R-6: `local/` y el tipo `private`.** Contenido mínimo de `local/` nueva: `local/.gitignore` con exactamente `*\n` (se ignora a sí mismo: nunca aparece en `git status` ni viaja con el repo: por clon, falla declarada de la investigación §4) y `local/README.md`. Si `local/` **ya tiene archivos versionados** (`git ls-files -z -- ':(icase)local/'` no vacío: **con `:(icase)` porque `Local/x` versionado no aparece con `local/`, medido**) → `refused: 'tracked-files'` con la lista; nunca se destrackea nada. Si `local/.gitignore` existe con otro contenido → `gitignore-exists`, no se pisa. Si `local/` existe **sin** versionados y **sin** `.gitignore`: se escribe solo `.gitignore` (`wx`) y la vista previa **lista los archivos sin versionar que dejarán de verse en `git status`**. Si el nombre real del disco difiere en mayúsculas → `case-collision`. **`private` solo admite crear, adoptar o dejar; nunca mover** (mover una carpeta ignorada por una regla de la raíz la deja visible: medido). **Adoptar** una carpeta privada (`private/`, `.private/`) exige `git check-ignore -q <carpeta>/.probe` verdadero; si no está ignorada: con versionados → `tracked-files`; sin versionados → se le escribe su `.gitignore` con `*` (como `local/`). En equipo `init` muestra siempre la línea `/local/` para el `.gitignore` compartido como opcional y **no la agrega**.
- **R-7: guarda de rutas (`isLinkOrOutside(main, rel, fs)`) y recorrido manual (`walkTree`).** `isLinkOrOutside` recorre **cada componente** de `rel` desde `main` con `lstat` (un enlace en cualquiera → `link-in-path`, `at: <componente>`), se detiene en el primer componente que no existe, y compara el `realpath` del primer ancestro existente con `realpath(main)` (afuera → `outside-project`). Se aplica al origen, al destino **y a sus padres**, a cada archivo que se lee o reescribe (`scanReferences`, `applyRewrites`, `findStray`), a cada carpeta que crea el esqueleto, a la ruta que devuelve `where` y a ambos extremos del deshacer. **Nunca se llama a `git mv` ni a `renameSync` si algún padre del origen o del destino es un enlace.** `walkTree(main, rel, fs) → { files: [{ path, size }], dirs: [path], links: [path], tooBig: boolean }` recorre con `readdirSync(dir, { withFileTypes: true })`, **no sigue** los enlaces (`Dirent.isSymbolicLink()` los pone en `links`) y corta en `MAX_FILES = 2000` o profundidad 12 con `tooBig: true` (**sin tope silencioso**: lo que no se miró entero nunca es "sin código"). El resultado va ordenado.
- **R-8: mecánica de un movimiento.** Ítems `{ kind: 'dir'|'file', from, to }` (rutas relativas a `main`, con `/`). Un directorio se mueve **entero** (incluye lo ignorado y lo sin versionar, **medido** con `git mv`). `tracked` = `git ls-files -z -- from` no vacío: **un `git mv -- from to` por ítem, con un solo origen** (con varios orígenes un fallo deja el primero movido y el índice sin actualizar: medido); si no, `fs.renameSync` (`git mv` de una carpeta solo sin versionar da `source directory is empty`: medido). Crea los directorios padre del destino que falten (los anota en `createdDirs`; sin padre, `git mv` falla: medido). **Renombrar solo cambiando mayúsculas** (`Docs` → `docs`, carpeta o archivo): `refused: 'case-only'`; el motivo real medido: en Windows `git mv` de una carpeta falla entero con `Invalid argument` (no a medias) y `renameSync` deja el disco en `docs` y el índice en `Docs/` sin que `git status` lo diga; la skill ofrece **adoptar**. **Un movimiento a medias se detiene, no se reintenta ni se revierte solo:** ver R-12.
- **R-9: guardas de un movimiento (`planMoves`; todas por ítem; cualquiera da `refused` con su `reason`; todas son duras: `force` no las toca).**
  1. `not-found`: el origen no existe. 2. `dest-exists`: el destino existe (archivo, carpeta o vacía): nunca se pisa ni se mezcla. 3. `dest-inside-source` / `source-inside-dest`. 4. `outside-project` / `link-in-path` (R-7) sobre origen, destino y padres, y **cualquier enlace en el árbol** (`walkTree().links` no vacío). 5. `case-collision`: algún componente existente del origen o del destino difiere en mayúsculas del nombre real del disco (`readdir`) o del índice (`git ls-files`): con `Docs/` en disco, mover a `docs/specs` crearía `Docs/specs` en el disco y `docs/specs` en el índice (medido). 6. `case-only` (R-8). 7. `dirty`: `git status --porcelain --untracked-files=no -- <from> <to>` no vacío; el mensaje **nombra el archivo** y dice que si no lo tocó nadie puede ser un programa que lo tiene abierto (con un archivo bloqueado `git status` lo muestra modificado: medido). 8. `contains-non-doc`: el árbol (o el archivo) tiene algún archivo cuya extensión **no está** en `DOC_EXT` (`md mdx txt rst adoc pdf png jpg jpeg gif svg webp csv docx xlsx pptx drawio excalidraw`; nombres sin extensión permitidos: `.gitignore`, `.gitkeep`, `README`, `LICENSE`, `NOTICE`): **lista de permitidos, falla cerrada** (`.json`, `.yml`, `.toml`, `.html`, `.css`, `.ipynb`, `Makefile`, `Dockerfile`, scripts sin extensión quedan fuera). 9. `matches-declared-paths`: algún archivo del árbol casa un patrón **declarado** de `test-paths`, `high-risk-paths`, `contracts` o `serial-paths` (R-3; `detail` nombra el patrón). 10. `tool-owned`: el origen es una carpeta de otra herramienta (R-15). 11. `too-big`: `walkTree().tooBig`. 12. `reserved-source`: el origen es `.git`, `.pignolo`, `.claude`, `node_modules`, `.github` o una carpeta de la lista de R-3. 13. `merge-in-progress`: hay merge, rebase, cherry-pick o bisect en curso (`MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD`, `BISECT_LOG` en el gitdir) y `index-locked`: existe `index.lock` en el gitdir (un IDE u otro git; - **R-10: referencias (`scanReferences`), qué se busca y dónde.** **Archivos a mirar:** `gitList(['ls-files','-z','-co','--exclude-standard'])` (versionados y sin versionar no ignorados; un fallo del listado → `refused: 'scan-failed'`) más `.gitignore`, `.github/**`, `.gitlab-ci.yml`, `package.json`, **excluyendo** y poniendo en `unscanned: [{ path, reason }]`: binarios (byte NUL en los primeros 8 KB: `binary`), > 1 MB (`too-large`), `.pignolo/state/**` (historia propia de pignolo, `state`), `node_modules/`, **`.env*`, `*.pem`, `*.key`, `*.p12`, `id_rsa*` y lo que `git check-ignore` marque como ignorado (nunca se abren: `private`)**, todo archivo que `isLinkOrOutside` marque (`link`: git lista y `git add` acepta archivos alcanzados por un junction, medido) y los que no son UTF-8 válido (`not-utf8`).   **Markdown (`.md`, `.mdx`): se resuelven TODOS los enlaces relativos de todos los archivos**, no se busca la cadena de la ruta vieja (un `[a](specs/a.md)` desde `doc/README.md` no la contiene). Formas que se entienden: `[t](dest)` y `[x]: dest` con destino relativo simple (sin esquema, sin `/` inicial, sin `<…>`, sin título, sin `%`, sin paréntesis), con `./`, con `\` y con sufijo `#ancla` o `?consulta`. Para cada enlace se calcula el destino viejo `T` desde la ubicación vieja `F` del archivo; con el mapa de movimientos del lote se obtienen la ubicación nueva `F'` y `T' = mover(T)`; el relativo nuevo sale de `F'` a `T'`; se reescribe si el texto cambia. Eso cubre en una sola regla los enlaces hacia adentro de lo movido, **los que salen de lo movido** (cambió su profundidad), los hermanos que no repiten la ruta, y los enlaces **entre dos carpetas movidas en el mismo lote**. Un enlace cuyo destino no existe se deja como está y no se cuenta. Una forma que no se entiende pero cuyo destino, resuelto a mano, cae dentro de lo movido → clase `markdown-unsupported` (**manual, frena**).
  **Lo no-markdown** (código, configuración, CI, `.gitignore`, `package.json`, otros) se busca por texto: la ruta vieja con `/`, con `\`, con `./` delante y sin barra final, **como segmento completo** (delimitada por inicio, comillas, espacio, `(`, `[`, `=`, `:` o `/` antes, y por `/`, comillas, `)`, `#`, espacio o fin después: `adoc/specs` y `doc/specsX` no cuentan). **Clases:** `markdown-link` y `outbound-link` (reescribibles); **manuales que frenan:** `code`, `config`, `ci`, `gitignore`, `package-json`, `other`, `markdown-unsupported`, `dirty-file`; **aviso que NO frena:** `markdown-text` (mención en prosa: con un origen de un solo segmento —`specs/`, `plans/`— casaría palabras comunes y el usuario aprendería a forzar). - **R-11: cuándo y cómo se reescribe.** Solo se reescribe un archivo **limpio** (`git status --porcelain -- <archivo>` vacío); uno con cambios sin guardar pasa a manual (`reason: 'dirty-file'`, frena). **Se reescribe por tramos de bytes**: solo cambia el destino del enlace y el resto del buffer queda idéntico (finales de línea mezclados, BOM, todo); antes de tocar, `Buffer.from(texto, 'utf8').equals(original)` (si no: `not-utf8`, no se escribe). Todo archivo reescrito se respalda antes (`backupFile`), se escribe atómico y su hash posterior va al registro. Una reescritura que no cambia ningún byte no se cuenta. **Una referencia manual que frena deja el ítem en `adopt` con `blockedBy: [<referencias>]`**; solo se mueve si el plan trae `force: true` para ese ítem (el usuario insiste: D-FS-B); las manuales quedan listadas como "arreglar a mano" y `verify` las vuelve a buscar. `force` **nunca** pasa una guarda de R-9.
- **R-12: registro, deshacer y movimiento a medias (`moves.json`).** `{ v: 1, ts, main, head, status: 'applying'|'applied'|'partial'|'undone', items: [{ kind, from, to, tracked, status: 'pending'|'done' }], createdDirs: [<ruta>], rewrites: [{ file, fileBefore, backup, sha256Before, sha256After, status: 'pending'|'done' }], mapEdits: [{ kind, before, after }] }`. Se escribe (creación exclusiva) **antes del primer movimiento con todo lo previsto**: los ítems, las carpetas que se van a crear, **cada reescritura con sus hashes antes y después** (salen de `planRewrites`) y los cambios del mapa (`before` es lo declarado, `null` si no había; `after` la ruta final). Se actualiza por ítem y por reescritura. **Un movimiento (o reescritura) que falla** (por ejemplo un archivo abierto por otro proceso: `EPERM`/`EBUSY` o `git mv` exit 128; medido: un ítem nunca queda a medias) **detiene el lote**: no sigue con los demás, no revierte solo, devuelve `{ ok: false, kind: 'partial', failed: { item, error }, done: [...], pending: [...], record }` (exit 3 del CLI) con el motivo y "cerrá el programa que tiene abierto `<archivo>` y reintentá, o `places.js undo --record <ruta>`"; el paso `adapt` queda `refused` y **los pasos siguientes de `init` no corren** (`skipped: 'adapt-failed'`, el mapa no se escribe). Si falla el primer movimiento y no se movió nada: `kind: 'failed'`, exit 1, registro `undone`.
  **`undoMoves({ record })` decide por el disco, no por el índice ni por `status`** (un corte entre el movimiento y la actualización del registro deja `pending` algo ya movido). **Lista cerrada de guardas del deshacer:** (1) `record.main` tiene el mismo `realpath` que el `main` actual (si no: exit 2 `wrong-repo`); (2) `isLinkOrOutside` sobre `from` y sobre `to` de cada ítem; (3) por ítem: `to` existe y `from` no → se revierte; `from` existe y `to` no → ya revertido, se saltea; **los dos existen → `source-exists`**; ninguno → `dest-missing`; (4) sin merge en curso y sin `index.lock`; (5) cada archivo reescrito: su hash actual es `sha256After` (se restaura) o `sha256Before` (ya restaurado, se saltea); otro valor → `modified-since` con la lista, **antes de mover nada**. **No se aplican** `dirty` (tras un `git mv` el índice tiene renombres `R`: la guarda negaría siempre el deshacer, medido), `contains-non-doc`, `reserved-source` ni `dest-inside-source`. **Orden:** validar todo → restaurar los archivos reescritos **en su ruta actual** (la de adentro de lo movido ya cambió) → revertir los ítems en orden inverso (`git mv -- to from` si `tracked`, si no `renameSync`) → `rmdirSync` de `createdDirs` de adentro hacia afuera, **solo las que estén vacías** (el padre del origen que quedó vacío —`doc/`— se informa y no se toca) → revertir `mapEdits` con `revertPlaces` en `project.md` → registro `undone`. **Idempotente y retomable:** un segundo `undo` sobre un registro `undone` (o con todo ya revertido en el disco) da `ok: true, already-undone` y cero cambios; un deshacer que falla a mitad deja el resto para el siguiente `undo` (exit 3 con la lista). `revertPlaces` toca **solo** la línea `places.<tipo>` y **solo si su valor actual es `after`** (la deja y lo avisa si cambió); el resto de `project.md` (lo que escribió el paso `project-md`) no se toca. Los registros no se podan automáticamente.
